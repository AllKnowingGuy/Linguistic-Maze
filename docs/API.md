# API

Данный файл описывает форматы данных и публичные методы, которые используются для расширения 
игры Linguistic Maze. С его помощью вы сможете создавать собственные диалоги, задания, уровни и даже добавлять 
новые типы проверки ответов.

> ## Глоссарий
> Диалог — сцена общения игрока с персонажем (монстром или NPC).
> 
> Задание (Challenge) — набор вопросов/задач, которые игрок решает в специальном режиме.
> 
> Респекты — внутриигровая валюта, накапливается за правильные ответы и тратится при ошибках.
> 
> Артефакты — предметы, позволяющие пропускать некоторые задания.

## Диалоги

Диалоги хранятся в папке `assets/data/dialogues/` в формате JSON. Пример: `intro.json`.

Пример общей структуры файла:
```bash
{
  "left": "Протагонист",             
  "right": "Монстр",                  
  "rightsprite": "monsters/level_0/enemy_at_exit.png",
  "ominous": false,                  
  "music": "Monster.wav",              
  "rpoints": 5,            
  "challenge": false,    
  "lines": [ ... ]
}
```

Поля файла:

- left – имя левого персонажа. 
- right – имя правого персонажа. 
- rightsprite – путь к спрайту правого персонажа относительно `assets/images/dialogue/`.
- ominous – логический флаг. Если `True`, перед диалогом будет проигрываться зловещая музыка (файл Monster.wav).
- music – имя файла из `assets/music/` для замены стандартной музыки. 
- rpoints – количество респектов, начисляемых игроку после завершения диалога.
- challenge – если `True`, после диалога автоматически запускается задание.
- lines – массив реплик.
- speaker – строка, определяющая, кто говорит: "left" или "right".
- text – текст реплики.
- bg – строка, задающая фон.
- jump – целое число или null. Указывает индекс следующей реплики (0‑база). -1 – завершить диалог. null – обычный переход к следующей реплике.
- action – объект или null. Если присутствует, диалог приостанавливается и ожидает действия игрока.
- type – строка, определяющая тип действия: "choosefrom" (кнопки выбора) или "savetyped" (сохранение текстового ввода без проверки).
- options – массив строк, варианты для кнопок.
- jumps – массив целых чисел или null, соответствующий каждому варианту. Указывает индекс следующей реплики. -1 – завершить диалог.

## Задание

Задания хранятся в `assets/data/challenges/level_N/`. Каждый файл представляет собой JSON-объект с одним массивом. 
Пример: `enemy_at_exit.json`.

Пример общей структуры файла:
```bash
{
    "windows": [
        {
            "title": "ЗАДАНИЕ 1",
            "text": "Ответь на главный вопрос мира.",
            "action": {
                "type": "savetyped",
                "answers": ["42", "67"],
                "checker": "plainequality",
                "correctcomments": ["Имеет смысл...", "Или нет?"],
                "incorrectcomments": ["Эх, не шаришь.", "Подумай ещё."],
                "correctrpoints": 2,
                "incorrectrpoints": -2
            }
        },
        {
        },
        {
            "title": "ЗАДАНИЕ 2",
            "text": "Почему?",
            "action": {
                "type": "choosefrom",
                "options": [...],
                "answers": ["Оно не имеет структуры"],
                "checker": "plainequality",
                "correctcomments": ["Признайся, сам код для этого писал?", "Как ты это понял?"],
                "incorrectcomments": ["Не повезло, не угадал.", "Мимо!"],
                "correctrpoints": 3,
                "incorrectrpoints": -1
            }
        }
    ]
}
```

Поля файла:

- title – заголовок, отображаемый сверху.
- text – текст вопроса.
- image – необязательное изображение, путь относительно assets/images/challenge/.
- action – объект с параметрами проверки ответа.
- type – строка: "textinput" (поле ввода) или "choosefrom" (кнопки выбора).
- options – массив строк, варианты для выбора (только для "choosefrom").
- answers – массив строк, правильные ответы (строки или регулярные выражения для чекера wordmatch).
- checker – имя чекера (см. раздел 3).
- correctrpoints – целое число, респекты за правильный ответ.
- incorrectrpoints – целое число, респекты за неправильный ответ (обычно отрицательное).
- artifact – строка, название артефакта, выдаваемого за правильный ответ.
- correctcomments – массив строк, случайные комментарии при правильном ответе.
- incorrectcomments – массив строк, случайные комментарии при неправильном ответе.
- threshold – число с плавающей точкой, порог для чекера sentiment_rubert (по умолчанию 0.6).

## Поддерживаемые чекеры введенного текста при прохождении заданий

- `plainequality` – сравнивает введённый текст с каждым значением из answers после удаления пробелов по краям и без учёта 
регистра. Если хотя бы одно совпадение, ответ правильный.
- `ling_terms` – ищет в ответе регулярное выражение (лингвист|язык|лингв|термин|фонет|социо|нейро). Возвращает True, если 
найдено совпадение.
- `wordmatch` – применяет регулярные выражения из answers к ответу игрока. Каждое выражение проверяется независимо; ответ 
считается правильным, если хотя бы одно совпало.
- `sentiment_rubert` – использует модель для анализа тональности. Возвращает `True`,
если оценка положительности (score) превышает threshold (по умолчанию 0.6). 
При ошибке (например, нет интернета) возвращается fallback-проверка на ключевые слова хорошо, помощь.

## Добавление нового чекера

Чтобы добавить собственный способ проверки, отредактируйте метод `check_current_answer` в классе **Challenge** 
(`src/levelBuilding/Challenge.py`). Добавьте новую ветку elif:

```bash
elif checker == 'my_checker':
    ...
    correct = some_condition(user_input)
```

После этого в JSON-файл можно использовать "checker": "my_checker".
